# 应用设置与持久化

Android 与 Windows 共用设置页、SettingsViewModel、AppSettings 和 SettingsRepository。

| 设置 | 默认值 | 含义 |
| --- | --- | --- |
| 后台监测 | 开启 | 允许后台网络监测；不代表授予系统后台权限 |
| 通知 | 开启 | 允许共享请求与连接状态通知 |
| 启动时开始监测 | 开启 | 应用启动后开始监测，不代表系统开机自启 |
| 热点空闲关闭 | 10 分钟 | 无客户端后关闭由应用拥有的热点；可选 5、10、15、30、60 分钟 |
| 共享请求方式 | 每次确认 | 或选择仅手动请求 |

设置已接入正式共享流程：后台监测控制网络轮询和 Android 前台服务；通知开关控制正式流程的提醒；“仅手动请求”禁用离线自动提醒，保留状态页请求入口；空闲时长用于本应用拥有热点的无客户端检查。启动监测默认打开，会在加载配对记录后主动恢复，并每 20 秒检查；不代表系统开机自启。Windows 服务广播由应用生命周期启动，与页面无关。

## 存储与失败处理

Repository 使用 shared_preferences 2.5.6 的 SharedPreferencesAsync，避免旧版单例读缓存与后台 isolate 写入不一致。整组偏好序列化为带版本号的 JSON，写入 networksharing.settings 单一键，避免多个字段分别写入产生混合配置。Android 使用插件的 DataStore 后端，Windows 使用本地应用偏好后端。偏好不跨设备同步，卸载或清除应用数据可能删除偏好。

缺少存储时加载默认值。当前版本为 1；未知版本、损坏 JSON 会显示读取失败并禁止编辑覆盖，用户可重试读取。未知枚举和不支持的时长回退到安全默认值。保存期间阻止后续编辑；写入失败时恢复此前界面值并提示用户，重载成功后可以重试。

当前联调实现另用 SharedPreferencesAsync 保存配对恢复令牌、设备授权和本应用拥有热点的 SSID 标记；热点密码仅在内存/通信中使用。设备授权为每次询问/自动允许/拒绝请求，在设备状态页设置。后续 CredentialVault 与安全存储迁移另行推进，不阻断本阶段使用功能；详见 application-sharing.md。

新增字段应同时更新模型、版本化序列化、默认值、设置页、测试及本文。新增可选字段可在 version 1 中回退默认值；破坏性更改须实现明确迁移并提升版本。后台服务默认只读偏好，设置写入保持在 SettingsRepository 单一入口。

## 验收

测试使用 shared_preferences 官方异步内存实现，覆盖默认值、保存后通过新 Repository 重新读取、未知字段值回退；ViewModel 测试覆盖读写失败、重试和销毁期间异步保存；UI 测试覆盖 320、390 和 1200 逻辑像素宽度。物理设备重启和 Windows 清洁安装仍需平台验收。
