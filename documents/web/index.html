01 / 场景与问题

一台设备断网，
另一台仍然在线

在宿舍、外出或出差时，用户常常需要手动打开热点、寻找密码，再在另一台设备上输入。步骤多，也容易中断。

PROBLEM 01

操作链路繁琐

切换设备、开启热点、复制并输入 Wi-Fi 信息，临时应急不够顺畅。

PROBLEM 02

平台能力不同

Android 与 Windows 的蓝牙、热点和后台权限各有边界，跨设备协同需要处理差异。

02 / 作品方案

用蓝牙发起请求，
用热点恢复连接

设备提前配对后，离线一端通过 BLE 通知对端；获准后由在线设备开启或复用热点，并传递接入信息。

02 · REQUEST

04 / 核心能力

从设备发现到网络恢复，
把关键步骤连起来

PAIR

设备配对

通过 BLE 发现并配对设备，保存配对关系，后续可尝试自动恢复连接。

REQUEST

按需请求

离线设备向在线伙伴请求共享网络；对端可逐次确认，也可设置自动处理策略。

CONNECT

协助接入

获准后尝试开启或复用热点、传递接入信息，并连接 Wi-Fi。

CHECK

确认网络

连接后检测互联网可达性，并在设备状态页显示请求和连接进度。

05 / 适用场景

少一点手动切换，
多一份连接保障

ON THE GO

外出途中

手机流量暂不可用时，尝试借助随身 Windows 电脑的网络。

AT HOME

宿舍与居家

一台设备仍在线时，为另一台设备提供临时网络接入路径。

实际热点启停和自动连接能力受 Android 版本、设备权限与厂商策略影响；部分设备可能需要额外授权。
